LunaVisual — защита от DDoS / ботов
===================================

ВАЖНО
-----
HTML/JavaScript сам по себе не может остановить сетевой DDoS. Защита должна
стоять ПЕРЕД сайтом (CDN/WAF) и отдельно на API/базе. В проект уже добавлена
серверная защита Supabase от частых вызовов RPC. Для внешнего сайта включите
Cloudflare по инструкции ниже.

1. Снова выполните supabase_setup.sql
------------------------------------
В Supabase -> SQL Editor выполните обновлённый supabase_setup.sql.
Он создаёт таблицу rpc_rate_limits и серверные лимиты:
- активация ключа: до 10 попыток / минуту на пользователя;
- генерация ключей: до 12 запросов / минуту (только администратор);
- запрос состояния лаунчера: до 120 запросов / минуту на пользователя.

Таблица rate-limit закрыта RLS и недоступна напрямую обычным пользователям.
Ограничение выполняется на сервере PostgreSQL, поэтому изменение JS в браузере
его не обходит.

2. Cloudflare для домена
------------------------
Если домен LunaVisual управляется через Cloudflare:
- DNS -> запись сайта должна быть Proxied (оранжевое облако), а не DNS only.
- SSL/TLS -> Full (strict), если origin поддерживает корректный HTTPS.
- Security -> DDoS protection / Managed rules: включить стандартные правила.
- Security -> Bots: включить доступную защиту от ботов.
- Включить Browser Integrity Check.
- В период атаки можно временно включить Under Attack Mode.

Рекомендуемые Rate Limiting rules для САЙТА (если тариф Cloudflare позволяет):
- /admin.html: 20 запросов / 10 секунд / IP -> Managed Challenge.
- /profile.html: 30 запросов / 10 секунд / IP -> Managed Challenge.
- статические HTML: 100 запросов / 10 секунд / IP -> Managed Challenge.

Не блокируйте обычные .css/.js/.png слишком жёстко: браузер загружает их пачкой.

3. Supabase Auth
----------------
В Supabase Dashboard -> Authentication:
- включите CAPTCHA / bot protection для регистрации и входа, если доступно;
- установите разумные Auth rate limits;
- отключите ненужные OAuth-провайдеры;
- не используйте service_role key в HTML/JS/лаунчере.

Publishable key может находиться в браузере. service_role key — НИКОГДА.

4. Что уже защищено в проекте
-----------------------------
- RLS для profiles и license_keys;
- генерация ключей только администратором;
- серверная активация ключей через RPC;
- серверный rate-limit для критичных RPC;
- закрытая таблица счётчиков rate-limit;
- лаунчер получает только данные текущего авторизованного пользователя.

5. При реальной атаке
---------------------
Смотрите Cloudflare Security Events и Supabase Logs. Если один endpoint
атакуют постоянно, временно ужесточите правило именно для него, а не для всего
сайта. Это снижает риск заблокировать обычных пользователей.
